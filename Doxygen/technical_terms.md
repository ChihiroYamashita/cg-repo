### バリュートリック座標（Barycentric Coordinates）

三角形の内部の点を表現するための座標系です。三角形の3つの頂点と、それに対する重み付けによって、任意の点の位置を表すことができます。

### インデックス
**インデックス**とは、配列やリストの**要素の位置を示す番号**です。
多くの言語で **0から始まります**。

例：

```cpp
int a[] = {10, 20, 30};
a[0] は 10、a[2] は 30←0,1,2がインデックス
```

### プリミティブとは

\*\*プリミティブ（primitive）\*\*は、**基本的な構成要素**を意味します。
文脈によって意味が異なりますが、共通して「もっとも小さく単純な単位」を指します。

---

#### 🔹 プログラミングでの意味

* **プリミティブ型（基本データ型）**
  言語に最初から備わっている基本の型
  例：`int`（整数）、`float`（小数）、`char`（文字）、`bool`（真偽値）など

---

#### 🔹 CGや3Dでの意味
**CGや3Dにおける「プリミティブ」とは、基本的な図形や構造のこと。**

* **プリミティブ図形**

🔹 代表的なプリミティブの例

* 点（Point）
* 線（Line）
* 三角形（Triangle）
* 四角形（Quad）
* 球、立方体、円柱 など（3Dモデリングでの「基本形」）
### 🔹 用途

* モデルの構成要素（例：三角形の集合でポリゴンモデルを作る）
* レンダリング単位（例：三角形単位で描画される）
* シェーダー処理の単位（例：1つのプリミティブに対して頂点シェーダーが走る）
---

#### ✅ ポイント

プリミティブは「最小単位」。
大きくて複雑なものを作る土台になります。

## ✅ バッファとは？

> **「一時的にデータをためておく場所」** のことです。

コンピュータで何かを「すぐに処理できない」「時間がかかる」「まとめて処理したい」というときに、**いったんデータをためる**ための箱や倉庫のようなものです。

---

## 🖥️ 例2：画像を描画するレイトレーシング

今あなたのコードでやっていることは、次のような流れです：

1. ピクセルごとにサンプルをたくさん取って（ノイズを減らすため）
2. 各サンプルの色を合計して（アキュムレーションバッファ）
3. サンプル数で割って平均して（カウントバッファ）
4. 最終的な色を画面に表示（フィルムバッファ）

---

## 🔁 各バッファの役割（もう一度、バッファ視点で）

| バッファ名         | 意味と目的                               |
| ------------- | ----------------------------------- |
| フィルムバッファ      | **最終結果を保存**：平均された画像（RGB）の最終版を格納     |
| アキュムレーションバッファ | **一時的な色の合計**をためておく：サンプルを全部足し算してる箱   |
| カウントバッファ      | **何回サンプリングしたか**を保存する：割り算で平均を出すために必要 |

---

## 💡 なぜこんなに分けてるの？

1回だけレイを飛ばした色では **ノイズが多すぎる**からです。

何回も飛ばして平均を取ることで、滑らかできれいな画像になります。だから：

* **何回飛ばしたか覚える（カウントバッファ）**
* **色を合計する（アキュムレーションバッファ）**
* **あとで平均して表示する（フィルムバッファ）**

---

### ①モデリング変換

void drawcube()で行う。

> glTranslate()やglRotate()を使いオブジェクトを任意の場所に配置するが，2Dグラフィックスや前項で述べた通り，アフィン変換によって，「オブジェクトのローカル座標系」を「移動・回転・拡大縮小」させるために「ワールド座標系」に変換した状態である．
> https://cad.lolipop.jp/work/class/OpenGL/1_OpenGL1x/CoordinateSystemsCamera.htm

平行移動などの処理をするとOpenGLが勝手にワールド座標系に変換してくれる。
```
// 1. オブジェクトを平行移動する
glTranslatef(1.0f, 1.0f, -0.0f);

// 2. オブジェクトをY軸周りに45度回転する
glRotatef(45.0f, 0.0f, 1.0f, 0.0f);

// 3. オブジェクトのサイズを倍に拡大する
glScalef(2.0f, 2.0f, 2.0f);
```
### ②視野変換
> モデリング変換が行われた段階では，世界(ワールド座標系)の中心を基準としてモデルが描かれるが，これを投影する前に，カメラを原点としてレンズの傾きなどカメラから見える状態の座標系に変換する．これが視野変換である．
> 本来なら視野変換もアフィン変換同様行列演算で行うが，OpenGL 1.x系ではこの部分はgluLookAt()を使いカメラの位置を指定することで，自動的に行われる．
### ③投影変換
MyOpenGLWidget::updateProjectionMatrix()内で行う。

投影変換とは
> - 視野変換で得られた「カメラを原点とした座標系で表現された世界(これはまだ3次元)」を2次元に落とし込む変換である．いわゆる **「パース図を描く」** 作業に相当する  
> OpenGL 1.x系では，この作業はglOrtho()(平行投影)
> もしくはgluPerspective()(透視投影)により，自動的に行われる．  
> この投影変換も，本質的には行列演算で行われる．


このため、OpenGL内ではただglOrtho()かgluPerspective()を設定すればOK
ここで初期設定されたwidth、height,orthoモードなどの情報を参考にモデルビュー行列を計算してGPUに送信する。
