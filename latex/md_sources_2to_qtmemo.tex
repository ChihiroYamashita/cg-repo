\hypertarget{md_sources_2to_qtmemo_autotoc_md36}{}\doxysubsubsubsection{\texorpdfstring{{\ttfamily display()} → {\ttfamily paint\+GL()}}{{\ttfamily display()} → {\ttfamily paint\+GL()}}}\label{md_sources_2to_qtmemo_autotoc_md36}
{\ttfamily paint\+GL()}が、\+GLUTの{\ttfamily display()}に相当するメインの描画関数です。シーン内のオブジェクト（座標軸、立方体）を描画し、最後に{\ttfamily \doxylink{drawfilm_8cpp_a443204766d01c1b7114034c955991bc8_a443204766d01c1b7114034c955991bc8}{draw\+Film()}}でレイトレーシング結果のテクスチャを描画する、という流れは同じです。

\DoxyHorRuler{0}
\hypertarget{md_sources_2to_qtmemo_autotoc_md38}{}\doxysubsubsubsection{\texorpdfstring{{\ttfamily resize()} → {\ttfamily resize\+GL()}}{{\ttfamily resize()} → {\ttfamily resize\+GL()}}}\label{md_sources_2to_qtmemo_autotoc_md38}

\hypertarget{md_sources_2to_qtmemo_autotoc_md40}{}\doxysubsubsubsection{\texorpdfstring{{\ttfamily idle()} → {\ttfamily QTimer} + カスタムスロット}{{\ttfamily idle()} → {\ttfamily QTimer} + カスタムスロット}}\label{md_sources_2to_qtmemo_autotoc_md40}
これが最も重要な違いです。

GLUTの{\ttfamily idle()}関数は、イベントがない時に常に呼ばれ続けるため、\+CPUを消費しながらバックグラウンドで計算を行うのに使われていました。しかし、同じことを\+Qtのメインスレッドで行うと、\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}\+GUIが応答しなくなりフリーズします\texorpdfstring{$\ast$}{*}\texorpdfstring{$\ast$}{*}。

Qtでは、{\ttfamily QTimer}を使ってこの処理を実装するのが定石です。
