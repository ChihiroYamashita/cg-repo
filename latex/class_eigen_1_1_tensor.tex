\subsubsection*{template$<$typename Scalar\+\_\+, \mbox{\hyperlink{level1__cplx__impl_8h_a4e8e1c1bb9d4e05fc671fc133ec9dc9b_a4e8e1c1bb9d4e05fc671fc133ec9dc9b}{int}} Num\+Indices\+\_\+, \mbox{\hyperlink{level1__cplx__impl_8h_a4e8e1c1bb9d4e05fc671fc133ec9dc9b_a4e8e1c1bb9d4e05fc671fc133ec9dc9b}{int}} Options\+\_\+ = 0, typename Index\+Type = Dense\+Index$>$\newline
class Eigen\+::\+Tensor$<$ Scalar\+\_\+, Num\+Indices\+\_\+, Options\+\_\+, Index\+Type $>$}
The tensor class. 

The Tensor class is the work-\/horse for all {\itshape dense} tensors within \doxylink{namespace_eigen}{Eigen}.

The Tensor class encompasses only dynamic-\/size objects so far.

The first two template parameters are required\+: 
\begin{DoxyTemplParams}{テンプレート引数}
{\em Scalar\+\_\+} & Numeric type, e.\+g. float, double, int or {\ttfamily std\+::complex\texorpdfstring{$<$}{<}float\texorpdfstring{$>$}{>}}. User defined scalar types are supported as well (see \doxylink{_topic_customizing__custom_scalar_user_defined_scalars}{here}). \\
\hline
{\em Num\+Indices\+\_\+} & Number of indices (i.\+e. rank of the tensor)\\
\hline
\end{DoxyTemplParams}
The remaining template parameters are optional -- in most cases you don\textquotesingle{}t have to worry about them. 
\begin{DoxyTemplParams}{テンプレート引数}
{\em Options\+\_\+} & A combination of either {\bfseries{\doxylink{group__enums_gaacded1a18ae58b0f554751f6cdf9eb13_ggaacded1a18ae58b0f554751f6cdf9eb13a77c993a8d9f6efe5c1159fb2ab07dd4f}{Row\+Major}}} or {\bfseries{\doxylink{group__enums_gaacded1a18ae58b0f554751f6cdf9eb13_ggaacded1a18ae58b0f554751f6cdf9eb13a0103672ae41005ab03b4176c765afd62}{Col\+Major}}}, and of either {\bfseries{\doxylink{group__enums_gaacded1a18ae58b0f554751f6cdf9eb13_ggaacded1a18ae58b0f554751f6cdf9eb13ad0e7f67d40bcde3d41c12849b16ce6ea}{Auto\+Align}}} or {\bfseries{\doxylink{group__enums_gaacded1a18ae58b0f554751f6cdf9eb13_ggaacded1a18ae58b0f554751f6cdf9eb13a56908522e51443a0aa0567f879c2e78a}{Dont\+Align}}}. The former controls \doxylink{group___topic_storage_orders}{storage order}, and defaults to column-\/major. The latter controls alignment, which is required for vectorization. It defaults to aligning tensors. Note that tensors currently do not support any operations that profit from vectorization. Support for such operations (i.\+e. adding two tensors etc.) is planned.\\
\hline
\end{DoxyTemplParams}
You can access elements of tensors using normal subscripting\+:


\begin{DoxyCode}{0}
\DoxyCodeLine{\mbox{\hyperlink{class_eigen_1_1_tensor}{Eigen::Tensor<double,\ 4>}}\ t(10,\ 10,\ 10,\ 10);}
\DoxyCodeLine{t(0,\ 1,\ 2,\ 3)\ =\ 42.0;}

\end{DoxyCode}


This class can be extended with the help of the plugin mechanism described on the page \doxylink{TopicCustomizing_Plugins}{Extending Matrix\+Base (and other classes)} by defining the preprocessor symbol {\ttfamily EIGEN\+\_\+\+TENSOR\+\_\+\+PLUGIN}.

{\itshape {\bfseries{Some notes\+:}}}


\begin{DoxyDescription}
\item[{\bfseries{Relation to other parts of \doxylink{namespace_eigen}{Eigen}\+:}} ]\hfill \\
The midterm development goal for this class is to have a similar hierarchy as \doxylink{namespace_eigen}{Eigen} uses for matrices, so that taking blocks or using tensors in expressions is easily possible, including an interface with the vector/matrix code by providing .as\+Matrix() and .as\+Vector() (or similar) methods for rank 2 and 1 tensors. However, currently, the Tensor class does not provide any of these features and is only available as a stand-\/alone class that just allows for coefficient access. Also, when fixed-\/size tensors are implemented, the number of template arguments is likely to change dramatically. 
\end{DoxyDescription}
